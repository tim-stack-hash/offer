# Smart Dunyo Bot

Telegram-бот на `python-telegram-bot` 22: информация о колониях (локации, справочники, образцы заявлений), гостиницы, адвокаты с отзывами, инструкции по переводу денег, поддержка и обратная связь. К нему прилагается веб-панель администратора только для чтения.

## Структура проекта

```
.
├── main.py                  # точка входа (python main.py или python -m bot)
├── bot/
│   ├── app.py               # сборка приложения, persistence, обработчик ошибок
│   ├── config/              # настройки
│   │   ├── settings.py      #   переменные окружения (.env) и их проверка
│   │   ├── constants.py     #   ссылки, ID чатов по умолчанию, лимиты
│   │   └── paths.py         #   пути к медиа и данным
│   ├── content/             # все тексты на трёх языках (texts/) и справочные данные
│   ├── keyboards/           # inline- и reply-клавиатуры
│   ├── handlers/            # обработчики Telegram
│   │   ├── __init__.py      #   регистрация всех обработчиков и порядок групп
│   │   ├── patterns.py      #   распознавание локализованных кнопок
│   │   ├── common.py        #   общие помощники (язык, текущая клавиатура)
│   │   ├── subscription.py  #   обязательная подписка на группу
│   │   ├── colony/          #   выбор колонии и её меню
│   │   └── …                #   язык, телефон, поддержка, отзывы, адвокаты, одежда, админка
│   ├── services/            # логика без привязки к обработчикам (подписка, медиа, профиль)
│   ├── jobs/                # задачи по расписанию (рассылка, счётчик пользователей)
│   ├── database/            # SQLite: подключение, схема, запросы
│   └── web/                 # веб-панель администратора (Flask + Waitress)
├── assets/                  # картинки и видео, которые отправляет бот
├── data/                    # база и состояние бота (создаётся автоматически, не в git)
├── docs/                    # справочные материалы
├── scripts/                 # скрипты запуска
└── tests/                   # тесты (pytest)
```

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt        # для разработки: requirements-dev.txt
cp .env.example .env                              # и заполните значения
```

## Настройки (`.env`)

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_USER_IDS` | да | Telegram ID администраторов через запятую |
| `SUPPORT_CHAT_ID` | нет | Группа, куда приходят обращения в поддержку |
| `FEEDBACK_CHAT_ID` | нет | Группа, куда приходят предложения и жалобы |
| `LAWYER_REVIEWS_CHAT_ID` | нет | Канал, куда публикуются отзывы об адвокатах |
| `PROTECT_CONTENT` | нет | `true`: сообщения бота нельзя переслать или сохранить |
| `DATABASE_PATH` / `PERSISTENCE_PATH` | нет | Другое расположение базы и файла состояния |
| `LOG_LEVEL` | нет | Уровень логирования (`INFO` по умолчанию) |

Бот проверяет настройки при старте и сразу сообщает, если что-то задано неверно.

## Запуск

```bash
./scripts/run_bot.sh            # macOS / Linux
scripts\run_bot.bat             # Windows (или scripts\run_bot.ps1)
python -m bot                   # напрямую
```

Настройки берутся из `.env` или из переменных окружения (например, `Environment=` в systemd). Если чего-то не хватает, бот при старте пишет одну понятную строку с ошибкой.

Бот запоминает язык, выбранную колонию и незавершённые диалоги в `data/bot_state.pickle`, поэтому после перезапуска пользователям не нужно начинать заново. Если `bot_users.sqlite3` лежит в корне проекта (так было до переезда в `data/`), при первом запуске база переносится в `data/` автоматически.

## Медиафайлы

Все картинки и видео лежат в `assets/` и имеют латинские имена: кириллица в именах файлов ломается при переносе через архивы на Windows-сервер. Пути перечислены в `bot/config/paths.py`.

| Файл | Что это | Если файла нет |
|---|---|---|
| `assets/images/money_transfer/smart.jpg` | первая картинка инструкции по переводу | пропускается, видео отправляются |
| `assets/images/lawyers/tima.jpg` | фото адвоката в карточке | карточка отправляется без фото |

После первой отправки Telegram `file_id` сохраняется в базе, и дальше файлы не загружаются повторно.

## Где заполнять данные

Если по кнопке нет информации, бот отвечает «📭 Данных нет» (по-узбекски «Ma'lumot yo'q» / «Маълумот йўқ»). Чтобы вместо этого появились данные, заполните нужный файл:

| Что | Где |
|---|---|
| Гостиницы: локация и телефон | `bot/content/colonies/groups.py`, `HOTEL_INFO` |
| Локации и родительские группы колоний | `bot/content/colonies/groups.py`, `COLONY_COORDINATES` и `COLONY_GROUP_LINKS` |
| Справочник контактов колонии | `bot/content/colonies/directory_data.py` |
| Адвокаты | `bot/content/lawyers.py`, фото в `assets/images/lawyers/` |
| Регионы и продавцы одежды | `bot/content/clothing_regions.py`, `bot/content/texts/clothing.py` |
| Магазин и такси | данных пока нет, бот отвечает «Данных нет» |

## Тексты и оформление

Все тексты интерфейса на трёх языках лежат в `bot/content/texts/`. Тест не даёт добавить текст без перевода хотя бы на один язык. Заголовки выделены жирным через HTML-разметку: такие сообщения отправляются с `parse_mode=HTML`, а всё, что в них подставляется, экранируется функциями `escape` и `bold` из `bot/handlers/common.py`. Тесты проверяют разметку каждого сообщения так же строго, как Telegram.

## Требования к чатам

- **Обязательная группа** [@smartdunyopaygroup](https://t.me/smartdunyopaygroup). Бот должен быть в ней **администратором**: иначе Telegram не присылает события о вступлении. Подтверждённое членство кешируется на 2 минуты. Если Telegram не ответил на проверку, пользователь пропускается, а ошибка пишется в лог.
- **Группы поддержки и обратной связи** должны быть группами или супергруппами, а не каналами. Бот должен в них состоять.
- **Канал отзывов**: бот должен быть администратором с правом публикации.

## Ответы на обращения

Администраторы из `ADMIN_USER_IDS` и пользователи из `SUPPORT_REPLY_USER_IDS` (`bot/config/constants.py`) отвечают пользователю через Reply на сообщение бота с обращением в группе поддержки или обратной связи. Бот копирует ответ пользователю и подтверждает доставку.

## Рассылка инструкций по переводу

Каждый день в 08:00 и 20:00 (UTC+05:00) бот спрашивает зарегистрированных пользователей, прислать ли инструкции. Дополнительно вопрос приходит после каждых 20 учтённых действий пользователя и по кнопке «💸 Перевести деньги». Медиа лежат в `assets/` (список в `bot/config/paths.py`). Отсутствующие файлы пропускаются. Telegram `file_id` кешируется в базе, чтобы видео не загружались повторно.

## Админка

- `/admin`: число пользователей и выгрузка CSV.
- `/admin2`: статистика нажатий и выгрузка истории (время в UTC+05:00).
- Веб-панель (`./scripts/run_web_admin.sh` или `python -m bot.web`) слушает `127.0.0.1:$WEB_ADMIN_PORT` и защищена Basic Auth (`WEB_ADMIN_USERNAME`, `WEB_ADMIN_PASSWORD` от 16 символов). Для доступа из интернета ставьте перед ней HTTPS reverse proxy (Caddy или Nginx).

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

`tests/test_flows.py` прогоняет настоящее приложение (все обработчики, проверку подписки, диалоги, сохранение состояния) поверх поддельного Bot API из `tests/telegram_stub.py`, без сети и без токена. Сценарии: путь от `/start` до локации колонии, обязательная подписка, обращение в поддержку и ответ администратора, отзыв об адвокате, инструкции по переводу, перезапуск бота.
